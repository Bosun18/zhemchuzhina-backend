# API для фронтенда

Документация REST API отеля «Жемчужина» для клиентского приложения (сайт/SPA).

## Базовая информация

- Базовый префикс: `/api`
- Формат ответов: `JSON`
- Авторизация: **Laravel Sanctum**, токен передаётся в заголовке
  `Authorization: Bearer {token}`
- Эндпоинты, требующие авторизации, помечены 🔒

## Аутентификация

### Регистрация — `POST /api/register`

| Поле | Правила |
|---|---|
| `name` | required, string, max:255 |
| `email` | required, email, unique:users |
| `password` | required, string, min:8, confirmed (нужно поле `password_confirmation`) |
| `city` | required, string, max:255 |

Регистрация автоматически назначает роль `guest`.

Ответ `201`:
```json
{
  "user": {
    "id": 1,
    "name": "Иван Иванов",
    "email": "ivan@example.com",
    "city": "Москва",
    "role": "guest"
  },
  "token": "1|xxxxxxxxxxxxxxxxxxxx"
}
```

### Вход — `POST /api/login`

| Поле | Правила |
|---|---|
| `email` | required, email |
| `password` | required, string |

Ответ `200` — структура такая же, как при регистрации (`user` + `token`).
При неверных данных — `422` с ошибкой в поле `email`: «Неверный email или пароль.»

### Выход — `POST /api/logout` 🔒

Удаляет текущий токен доступа.

Ответ `200`:
```json
{ "message": "Выход выполнен успешно" }
```

## Профиль 🔒

### Получить профиль — `GET /api/profile`

Ответ `200`:
```json
{
  "id": 1,
  "name": "Иван Иванов",
  "email": "ivan@example.com",
  "city": "Москва",
  "role": "guest"
}
```

### Обновить профиль — `PATCH /api/profile`

| Поле | Правила |
|---|---|
| `name` | sometimes, string, max:255 |
| `city` | sometimes, string, max:255 |
| `password` | sometimes, string, min:8, confirmed |

Все поля необязательны — передавайте только то, что нужно изменить.
Ответ `200` — обновлённый профиль (формат как в `GET /api/profile`).

## Номера

### Список номеров — `GET /api/rooms`

Возвращает только активные номера (`is_active = true`), отсортированные по номеру комнаты.

Ответ `200`:
```json
[
  {
    "id": 1,
    "number": 1,
    "floor": 1,
    "type": {
      "id": 1,
      "name": "Стандарт",
      "max_guests": 3,
      "description": "..."
    }
  }
]
```

### Карточка номера — `GET /api/rooms/{room}`

Ответ `200` — объект номера в том же формате, что и в списке.

### Доступность номеров на даты — `GET /api/rooms/availability`

Query-параметры:

| Параметр | Правила |
|---|---|
| `check_in` | required, date, не раньше сегодняшнего дня |
| `check_out` | required, date, позже `check_in` |

Пример: `GET /api/rooms/availability?check_in=2026-07-01&check_out=2026-07-05`

Ответ `200` — список активных номеров с дополнительным полем `is_available`:
```json
[
  {
    "id": 1,
    "number": 1,
    "floor": 1,
    "type": { "...": "..." },
    "is_available": true
  }
]
```

## Бронирования 🔒

### Мои бронирования — `GET /api/my-bookings`

Ответ `200` — список бронирований текущего пользователя (от новых к старым):
```json
[
  {
    "id": 10,
    "check_in": "2026-07-01",
    "check_out": "2026-07-05",
    "guests_count": 2,
    "status": "pending",
    "comment": "Поздний заезд",
    "room": {
      "id": 1,
      "number": 1,
      "type": "Стандарт"
    }
  }
]
```

Возможные значения `status`: `pending`, `confirmed`, `cancelled`.

### Создать бронирование — `POST /api/bookings`

| Поле | Правила |
|---|---|
| `room_id` | required, существует в `rooms` |
| `check_in` | required, date, не раньше сегодняшнего дня |
| `check_out` | required, date, позже `check_in` |
| `guests_count` | required, integer, min:1 |
| `comment` | nullable, string, max:1000 |

Дополнительные проверки (ошибки `422`):
- `guests_count` не может превышать `max_guests` типа номера → ошибка в поле `guests_count`
- номер уже забронирован (статус не `cancelled`) на пересекающиеся даты → ошибка в поле `room_id`: «Номер занят на выбранные даты.»

Новое бронирование создаётся со статусом `pending`.
Ответ `201` — объект бронирования (формат как в «Мои бронирования»).

### Отменить бронирование — `DELETE /api/bookings/{booking}`

Доступно владельцу бронирования или персоналу (`admin`, `director`, `developer`).
Иначе — `403 Forbidden`.

Переводит бронирование в статус `cancelled`. Ответ `200` — обновлённый объект бронирования.

## Новости

### Список новостей — `GET /api/news`

Возвращает только опубликованные новости (`is_published = true`), отсортированные по дате публикации (сначала новые).

Ответ `200`:
```json
[
  {
    "id": 1,
    "title": "Открытие летнего сезона",
    "content": "...",
    "image": "news/xxxx.jpg",
    "published_at": "2026-06-01T10:00:00.000000Z"
  }
]
```

### Карточка новости — `GET /api/news/{news}`

Возвращает `404`, если новость не опубликована. Иначе — объект новости.

## Отзывы

### Список отзывов — `GET /api/reviews`

Возвращает только отзывы со статусом `approved`, отсортированные от новых к старым.

Ответ `200`:
```json
[
  {
    "id": 1,
    "rating": 5,
    "text": "Отличный отель!",
    "user": "Иван Иванов",
    "created_at": "2026-06-01T12:00:00.000000Z"
  }
]
```

### Оставить отзыв — `POST /api/reviews` 🔒

| Поле | Правила |
|---|---|
| `booking_id` | required, integer, существует в `bookings` |
| `rating` | required, integer, от 1 до 10 |
| `text` | required, string, max:2000 |

Дополнительные проверки (ошибка `422` в поле `booking_id`):
- бронирование должно принадлежать текущему пользователю и иметь статус `confirmed`
- на одно бронирование можно оставить только один отзыв

Новый отзыв создаётся со статусом `pending` (требует модерации персоналом).
Ответ `201`:
```json
{ "id": 1, "rating": 5, "text": "Отличный отель!", "status": "pending" }
```

## Уведомления (колокольчик) 🔒

Всплывающие уведомления для текущего пользователя (те же события, что и
в email-рассылке: для гостя — статусы его бронирований и отзывов, для
персонала — новые регистрации, бронирования и отзывы на модерацию).

Рекомендуется опрашивать `unread-count` раз в N секунд (например, 30) для
обновления бейджа на колокольчике, а полный список запрашивать при открытии
выпадающего меню.

### Список уведомлений — `GET /api/notifications`

Возвращает последние 50 уведомлений пользователя (от новых к старым).

Ответ `200`:
```json
[
  {
    "id": "9f1c1e4a-1b2c-4d3e-8f9a-0b1c2d3e4f5a",
    "title": "Бронирование подтверждено",
    "body": "Ваше бронирование №1 на 01.07.2026 — 05.07.2026 подтверждено.",
    "icon": "heroicon-o-check-circle",
    "color": "success",
    "url": "https://example.com/admin/bookings/10/edit",
    "read_at": null,
    "created_at": "2026-06-08T12:00:00.000000Z"
  }
]
```

`url` — необязательное поле, ссылка на связанную запись (есть не у всех
уведомлений, например, у уведомлений гостю чаще всего отсутствует).
`read_at` — `null`, если уведомление не прочитано.

### Счётчик непрочитанных — `GET /api/notifications/unread-count`

Ответ `200`:
```json
{ "count": 3 }
```

### Отметить уведомление прочитанным — `PATCH /api/notifications/{id}/read`

`{id}` — UUID уведомления из списка. Если уведомление не принадлежит текущему
пользователю — `404`.

Ответ `200`:
```json
{ "status": "ok" }
```

### Отметить все уведомления прочитанными — `POST /api/notifications/read-all`

Ответ `200`:
```json
{ "status": "ok" }
```

## Коды ошибок

| Код | Когда возникает |
|---|---|
| `401` | запрос без токена / с недействительным токеном к защищённому эндпоинту |
| `403` | нет прав на действие (например, отмена чужого бронирования) |
| `404` | запись не найдена или недоступна (например, неопубликованная новость) |
| `422` | ошибка валидации — тело ответа содержит `message` и `errors` (объект полей с массивами сообщений) |
